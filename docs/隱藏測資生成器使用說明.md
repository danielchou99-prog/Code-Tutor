# AI 隱藏測資生成器使用說明

這份文件提供 Dev Compass 題目管理員使用。主要流程不需要自行撰寫測資產生器：完成題目與配分條件後，讓 AI 分析並建立各組隱藏測資，再由伺服器驗證後套用。

## 一、使用前準備

1. 使用具有「題目管理」權限的帳號登入。
2. 填好題目名稱、摘要、描述、輸入格式、輸出格式，以及至少一組有答案的公開範例。
3. 在「配分群組與隱藏測資」填寫每組得分條件，總分必須為 `100%`。
4. 先按「翻譯並儲存題目」。AI 分析資料庫中最後儲存的版本，不會讀取尚未儲存的修改。
5. 管理員帳號必須已在「設定 → AI / Groq」連接有效的 Groq API key。

## 二、主要畫面每一格要填什麼

### 每組測資數量

- 必填，範圍 `2`～`50`，建議第一次填 `10`。
- 代表每個配分群組各自建立幾筆，不是整題總數。
- 例：兩個群組、每組填 `10`，會準備 20 筆測資。
- 每組至少一筆是 `boundary` 邊界測資。

### 套用方式

- `取代各組現有測資`：清除各組舊測資後換成本批；第一次建立或整批重做時使用。
- `附加到各組末尾`：保留舊測資再補入本批；適合補強案例。

第一次操作建議選「取代各組現有測資」。

### 進階設定 → 起始 seed

- 已有預設值 `1`，一般不需修改；範圍 `0`～`2147400000`。
- seed 控制可重現的亂數結果。相同版本、seed、策略和群組會產生相同輸入。
- 例：填 `1000` 時從 seed 1000 開始；不同群組會使用不同 seed 區段，避免重複。
- 只有要重現舊批次或另外補一批資料時才調整。

### AI 分析並產生測資

按下後，系統會：

1. 讀取最後儲存的完整公開題目、範例、執行限制及每組條件。
2. 從條件解析各組需要覆蓋的數值邊界。
3. 請 AI 建立 Generator、Reference Solution 和必要時的 Validator。
4. 在隔離 Docker 中確認標準解答通過全部公開範例。
5. 分別產生每組測資並計算正確輸出。
6. 拒絕空白、重複、超限、執行失敗或沒有覆蓋邊界的資料。
7. 建立伺服器草稿；此時不修改正式 Judge。

### 待套用的測資摘要

| 顯示內容 | 意思 | 範例 |
| --- | --- | --- |
| 組別 | 測資所屬群組 | 第一組 |
| 接受筆數 | 通過檢查的數量 | 10 筆 |
| 邊界證據 | 實際值與條件目標 | `999999 ≈ 1000000` |
| seed | 可重現該邊界案例的種子 | `seed 1002` |
| 嘗試 | 系統產生過的候選數 | 20 |
| 捨棄非法 | 空白、過大或 Validator 拒絕數 | 0 |
| 捨棄重複 | 與新批次或正式測資重複數 | 1 |

邊界驗證採目標值 `±1%`，且最少容許差距 `1`。最大值是 `10^6` 時，`1000000`、`999999` 都合格，`500000` 不合格。

### 套用全部測資

- 按下前，測資只在管理員專用的伺服器草稿。
- 按下後，才依摘要中的組別加入正式 Judge。
- 套用完成後會重新載入題目與各組測資數量。

## 三、完整範例：兩數相加

題目資料：

- 題目名稱：兩數相加
- 描述：給定整數 `A`、`B`，輸出 `A + B`。
- 輸入格式：一行包含兩個整數。
- 輸出格式：輸出兩數總和。
- 範例輸入：`1 2`
- 範例輸出：`3`

測資與計分：

- 第一組 40 分：`0 ≤ A, B ≤ 100`
- 第二組 60 分：`-10^6 ≤ A, B ≤ 10^6`

生成欄位：

- 每組測資數量：`10`
- 套用方式：`取代各組現有測資`
- 起始 seed：保持 `1`

預期摘要：

- 第一組 10 筆，邊界證據為 `100` 或 `99`。
- 第二組 10 筆，邊界證據為 `1000000` 或 `999999`。
- AI 標準解答必須先對 `1 2` 輸出 `3`，否則整批被拒絕。

## 四、系統如何判斷邊界

- `n ≤ 1000` → 目標 `1000`
- `1 ≤ n ≤ 10^6` → 目標 `1000000`
- `n ≤ 2**20` → 目標 `1048576`

系統優先讀取該組條件。如果該組寫「無額外限制」，會回看整題描述、輸入格式及其他群組條件。Generator 也會收到群組編號，因此能依第一組、第二組產生不同資料。

如果題意沒有可辨識的數值，預設邊界目標為 `1`。此時應補上明確條件，讓驗證更有意義。

## 五、常見錯誤

- `請先儲存題目`：先按頁面底部的「翻譯並儲存題目」。
- `Connect Groq...`：到「設定 → AI / Groq」連接有效 API key。
- `AI reference solution did not pass public sample`：題意、格式或公開範例可能矛盾，或 AI 解答不正確；系統不會套用。
- `Boundary coverage failed`：將「大型資料」改成 `1 ≤ n ≤ 10^6` 之類的明確條件後重試。
- 有效數量不足：Generator 變化不足、Validator 太嚴格或資料重複；更換起始 seed 後重試。

## 六、進階手動生成模式

只有 AI 無法正確處理特殊題型時才展開。

| 欄位 | 必須放入什麼 | 範例 |
| --- | --- | --- |
| 版本名稱 | 英數字及 `.`、`_`、`-`，最多 40 字元 | `v2-boundary` |
| 目標配分群組 | 本次要處理的群組 | 第二組 |
| Generator | 讀 seed、策略、群組編號，輸出一筆完整輸入 | Python/C++ 完整程式 |
| Reference Solution | 讀取測資並輸出唯一正確答案 | 官方完整解答 |
| Validator | 選用；合法 exit 0，不合法 exit 1 | 範圍檢查程式 |
| 測資策略 | Generator 實際支援的資料類型 | boundary、large_random |
| 產生數量 | 每批 1～100 筆 | 20 |
| 起始 seed | 第一筆候選的種子 | 2001 |
| 加入方式 | 取代或附加 | 取代 |

舊 Generator 只讀前兩行仍可使用；新版第三行是群組編號。

## 七、安全與驗收

- AI 只收到公開題目、公開範例與群組條件，不會收到既有隱藏測資。
- AI 程式必須在 Docker 隔離環境執行並通過檢查。
- 隱藏 Input／Expected Output 不會提供給一般使用者或 AI Tutor。
- 未按「套用全部測資」前，不修改正式 Judge。

驗收清單：

- [ ] 每組接受筆數符合設定。
- [ ] 每組都有邊界證據。
- [ ] 最大值 `10^6` 的題目至少一筆接近 `10^6`。
- [ ] 正確程式 Submit 得到 100 分。
- [ ] 只符合第一組限制的程式不能取得第二組分數。
- [ ] 一般使用者看不到隱藏輸入或輸出。
