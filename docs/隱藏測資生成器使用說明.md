# 隱藏測資生成器使用說明

這份文件提供 Dev Compass 管理員使用。它說明如何用程式自動產生 Judge 的隱藏輸入，並由標準解答算出正確輸出。

## 一、先理解三個程式

### Generator（測資產生器）

Generator 負責「出題」。系統每次執行它時，會從標準輸入提供兩行資料：

1. 第一行是固定的 `seed`，也就是亂數種子。
2. 第二行是測資策略名稱。

Generator 必須把一整筆題目輸入輸出到標準輸出。相同版本、seed 與策略應該產生相同結果，這樣出問題時才能重現。

### Reference Solution（標準解答）

Reference Solution 負責「解題」。系統會把 Generator 產生的內容交給它，再把它的標準輸出保存成該筆測資的正確答案。

標準解答必須是已確認正確的完整解法，不能直接使用尚未驗證的學生程式。

### Validator（輸入檢查器，可選）

Validator 負責檢查 Generator 產生的輸入是否符合題目格式與範圍：

- 合法：程式以 exit code `0` 結束。
- 不合法：程式以 exit code `1` 結束。

簡單題目可以不使用 Validator；格式複雜、限制很多或 Generator 還在調整時，建議加入。

## 二、使用前準備

- 使用已被 Dev Compass 認定為管理員的帳號登入。
- 題目必須至少先儲存一次；內容尚未完成時可以維持「未發布」。
- 題目至少要有一個配分群組，而且所有群組的占分合計必須是 `100%`。
- Supabase 必須已執行：
  - `202608250002_hidden_test_generation.sql`
  - `202608250003_hidden_test_quality_and_judge_metrics.sql`
- FastAPI、Supabase server-only secret，以及本機 Docker Compiler或 VPS Judge Worker 必須正常。

## 三、管理介面的操作順序

1. 進入「設定」。
2. 開啟「題目管理」。
3. 新增題目或選擇既有題目。
4. 先設定「第一組、第二組……」的得分條件、占分與執行限制。
5. 先按題目儲存；新題目沒有題號記錄前，不能建立機密產生版本。
6. 找到「自動產生隱藏測資」。
7. 輸入版本名稱，例如 `v1`、`v2-boundary`。
8. 選擇 Generator、Reference Solution，以及需要時的 Validator 語言。
9. 貼上三個程式後，按「安全儲存此版本」。
10. 選擇目標群組、測資策略、產生數量、起始 seed，以及取代或附加模式。
11. 按「產生並檢查」。
12. 查看接受數量、嘗試數量、非法數量、重複數量與資料大小摘要。
13. 摘要正確後，按「套用到配分群組」。
14. 儲存題目，最後再用 Submit 實際驗收配分與結果。

產生後不會立刻改寫正式隱藏測資。資料會先留在伺服器草稿，只有按下「套用到配分群組」才會進入 Judge。

## 四、版本、數量與 seed 怎麼設定

### 版本名稱

- 可使用英文字母、數字、`.`、`_`、`-`。
- 長度最多 40 個字元。
- Generator 或標準解答有任何邏輯變更時，建議建立新版本，不要混用舊結果。

### 產生數量

- 每批可以產生 1～100 筆。
- 系統會多嘗試一些 seed，讓非法或重複資料被捨棄後仍有機會補足數量。
- 若始終不足，代表 Generator 的資料變化太少、Validator 太嚴格，或與既有測資重複。

### 起始 seed

- seed 範圍是 `0`～`2147483647`。
- 相同版本加相同 seed 可以重現輸入。
- 下一批可以改用新的起始 seed，例如第一批從 `1` 開始，第二批從 `1001` 開始。

## 五、七種測資策略

| 策略 | 白話用途 | 常見內容 |
| --- | --- | --- |
| `basic` | 一般基本情況 | 小範圍、容易人工核對 |
| `boundary` | 邊界情況 | 最小值、最大值、臨界值 |
| `extreme` | 極端壓力 | 接近最大資料量或數值範圍 |
| `special` | 特殊結構 | 空集合、單一元素、特殊圖形或矩陣 |
| `duplicate` | 重複值 | 大量相同數字或重複節點 |
| `ordered` | 已排序結構 | 遞增、遞減或已分組資料 |
| `large_random` | 大型隨機 | 大量但可由固定 seed 重現的亂數資料 |

策略名稱只是系統交給 Generator 的指令。Generator 必須真的根據它改變產生方式，否則勾選多種策略也不會增加測資品質。

## 六、C++ 範例：A + B

### Generator（C++20）

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    unsigned int seed;
    string strategy;
    if (!(cin >> seed >> strategy)) return 1;

    mt19937 rng(seed);
    long long a = 0, b = 0;

    if (strategy == "boundary") {
        a = (seed % 2 == 0 ? -1000000000LL : 1000000000LL);
        b = (seed % 3 == 0 ? -1000000000LL : 1000000000LL);
    } else if (strategy == "special") {
        a = 0;
        b = static_cast<long long>(seed % 3) - 1;
    } else {
        uniform_int_distribution<long long> dist(-1000000, 1000000);
        a = dist(rng);
        b = dist(rng);
    }

    cout << a << ' ' << b << '\n';
    return 0;
}
```

### Reference Solution（C++20）

```cpp
#include <iostream>
using namespace std;

int main() {
    long long a, b;
    if (!(cin >> a >> b)) return 1;
    cout << a + b << '\n';
    return 0;
}
```

### Validator（C++20，可選）

```cpp
#include <iostream>
using namespace std;

int main() {
    long long a, b;
    if (!(cin >> a >> b)) return 1;
    if (a < -1000000000LL || a > 1000000000LL) return 1;
    if (b < -1000000000LL || b > 1000000000LL) return 1;

    string extra;
    if (cin >> extra) return 1;
    return 0;
}
```

## 七、Python 範例：A + B

### Generator（Python 3）

```python
import random
import sys

lines = sys.stdin.read().splitlines()
if len(lines) < 2:
    raise SystemExit(1)

seed = int(lines[0])
strategy = lines[1].strip()
rng = random.Random(seed)

if strategy == "boundary":
    a = -10**9 if seed % 2 == 0 else 10**9
    b = -10**9 if seed % 3 == 0 else 10**9
elif strategy == "special":
    a, b = 0, seed % 3 - 1
else:
    a = rng.randint(-10**6, 10**6)
    b = rng.randint(-10**6, 10**6)

print(a, b)
```

### Reference Solution（Python 3）

```python
a, b = map(int, input().split())
print(a + b)
```

### Validator（Python 3，可選）

```python
import sys

tokens = sys.stdin.read().split()
if len(tokens) != 2:
    raise SystemExit(1)

try:
    a, b = map(int, tokens)
except ValueError:
    raise SystemExit(1)

if not (-10**9 <= a <= 10**9 and -10**9 <= b <= 10**9):
    raise SystemExit(1)
```

## 八、取代與附加的差別

- 「取代群組現有測資」：清除目標群組原本的測資，再放入這一批。適合重新設計整組測資。
- 「加到群組末尾」：保留原本測資，再加入新測資。適合補強某些邊界情況。

使用取代前先確認目標是正確的第一組、第二組。隱藏測資套用後不會顯示完整內容給一般使用者。

## 九、系統會自動檢查什麼

- Generator、Validator 或 Reference Solution 是否編譯／執行成功。
- 輸入是否空白或超過大小限制。
- 新測資彼此是否重複。
- 是否和資料庫已保存的測資重複。
- Validator 是否接受輸入。
- Reference Solution 是否產生可用的正確輸出。
- 執行是否逾時、超出輸出限制或被隔離環境拒絕。

Judge 比對輸出時會統一換行格式，並忽略每一行結尾的空白與最後多餘空行；仍建議標準解答輸出乾淨且固定的格式。

## 十、常見錯誤

### 「請先儲存題目」

新題目尚未在資料庫取得題號。先以未發布狀態儲存，再建立產生版本。

### 「找不到版本」或按鈕不能按

先填入 Generator 與 Reference Solution，按「安全儲存此版本」，再從「已儲存版本」選擇它。

### 產生數量不足

- Generator 產生太多相同資料。
- Validator 拒絕太多資料。
- seed 沒有真正參與產生邏輯。
- 某種策略的可用組合數小於要求數量。

先用較小數量測試，再增加資料變化或調整策略比例。

### Generator 或標準解答逾時

檢查是否有無限迴圈、輸出過大，或演算法無法在題目時間限制內完成。

### Compiler unavailable

本機需啟動 Docker Desktop並確認 Compiler image 存在；VPS 則需確認 API、Judge Worker 與 Docker 服務健康。

## 十一、安全規則

- 不要把 Generator、Reference Solution、Validator 或真正的隱藏測資貼到公開題意、範例、標籤或 AI 對話。
- 這些程式只應透過管理員介面送到後端；儲存成功後，表單會清除原始碼。
- 瀏覽器只會收到 batch ID、雜湊、大小及品質摘要，不會收到隱藏 Input 或 Expected Output。
- 一般 Supabase `anon` 與 `authenticated` 角色無權讀取產生版本及伺服器測資草稿。
- 不要把 Supabase secret key、Groq API key 或其他 server-only secret 放進 Generator 程式。
- 發布題目前，至少用一份人工可計算的小測資交叉驗證標準解答。

## 十二、建議驗收清單

- [ ] 相同版本、seed 與策略重跑時，輸入可以重現。
- [ ] 每種勾選策略都實際產生不同類型的資料。
- [ ] Validator 可以拒絕一筆刻意製造的不合法輸入。
- [ ] Reference Solution 對人工小範例輸出正確。
- [ ] 品質摘要中的接受數等於預期數量。
- [ ] 套用到正確的配分群組，群組總分仍為 100%。
- [ ] 一份正確程式 Submit 得到 100 分。
- [ ] 一份只處理基本情況的程式只取得對應群組分數。
- [ ] 一般使用者、公開 API 與 AI Tutor 看不到隱藏輸入和正確輸出。
