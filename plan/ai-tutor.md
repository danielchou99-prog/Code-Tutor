# Code Tutor AI Tutor 第一版計畫

- 文件狀態：執行中
- 最後更新：2026-08-09
- 前置條件：帳號登入、Supabase AI connection migration、Groq API Key 安全連線皆已驗收

## 一、目標

讓使用者在專案程式頁中，使用自己的 Groq API Key 對目前的 `main.cpp` 執行「分析程式碼」、「解釋錯誤」、「提供提示」，也能輸入自己的問題，並逐步看到 AI 回覆。

第一版不讓 AI 直接修改或儲存程式，避免未確認的內容破壞使用者檔案。

## 二、目前狀態

- [x] 使用者可以登入並安全連接 Groq。
- [x] Groq Key 只以加密形式儲存在 Supabase，前端無法讀回完整 Key。
- [x] 程式頁已有 AI Tutor 外觀與三個快捷按鈕，但尚未連接真實 AI。
- [x] 已確認 Groq 官方目前支援 Chat Completions 串流，且 `llama-3.3-70b-versatile` 列於免費方案限制表。

## 三、執行步驟與簡易說明

### 1. 建立後端 AI Tutor 服務

- [x] 從使用者自己的 Supabase 記錄讀取加密 Groq Key，僅在後端記憶體中解密。
- [x] 建立 Groq Chat Completions adapter，支援逐段串流回覆。
- [x] 使用固定的程式教學提示詞，限制回覆範圍並依介面語言回答。
- [x] 區分未連接、無效 Key、網路限制、Groq 額度限制與暫時故障。

簡易說明：瀏覽器只把程式與問題送到 Code Tutor 後端；真正的 Groq Key 永遠不會傳回瀏覽器。

### 2. 建立安全 API

- [x] 新增需登入才能使用的 `POST /api/ai/tutor`。
- [x] 限制程式碼、錯誤訊息與自訂問題長度。
- [x] 回應使用純文字串流，並確保錯誤與 log 不包含 API Key 或完整敏感內容。

簡易說明：輸入限制可避免意外送出過大的內容；登入驗證可確保每個人只能使用自己的 Key。

### 3. 串接程式頁

- [x] 將目前編輯器內容與最近一次執行結果提供給 AI Tutor。
- [x] 啟用 Analyze Code、Explain Error、Give Hint 三個按鈕。
- [x] 加入可輸入自訂問題的欄位、送出、載入、停止與錯誤狀態。
- [x] 回覆區可捲動並保留本次開啟專案期間的對話。
- [x] 加入繁體中文與英文介面文字；程式碼與按鈕既有固定英文不受影響。

簡易說明：快捷按鈕會自動帶入目前程式；Explain Error 也會帶入最近一次執行的錯誤，使用者不需要複製貼上。

### 4. 免費額度與保護

- [x] 使用使用者自己的 Groq Key，不由網站共用付費 Key。
- [x] 前端與後端都限制每位使用者一次只能有一個進行中的 AI 請求，並提供取消功能。
- [x] 對 Groq `429` 額度限制提供清楚提示，不自動重試造成更多消耗。
- [x] 第一版限制回答長度，降低免費 token 用量。

簡易說明：費用與額度屬於使用者自己的 Groq 帳號；Code Tutor 不會在背景自動呼叫 AI。

### 5. 測試與文件

- [x] 後端測試認證、Key 解密、提示內容、串流解析與各種錯誤。
- [x] 前端執行 ESLint、TypeScript 與 production build。
- [x] 後端執行 pytest（42 項通過、9 項依環境略過）與套件相依檢查。
- [ ] 更新計畫狀態並完成真實 Groq 人工驗收。

簡易說明：自動測試先確認安全邊界，最後再用真實帳號確認串流畫面與教學回答。

## 四、驗收方式

1. 未登入或沒有連接 Groq 時，AI Tutor 不會送出成功，並顯示可理解的提示。
2. Analyze Code 能根據目前 `main.cpp` 說明正確性、複雜度與改善方向。
3. Explain Error 能參考最近一次編譯或執行錯誤。
4. Give Hint 只提供循序提示，不直接取代使用者完成整份答案。
5. 自訂問題可以送出，回答會逐步顯示，使用者可以停止。
6. API 回應、瀏覽器儲存、Git 與 log 都不包含完整 Groq Key。
7. 重新整理或切換專案不會自動呼叫 AI，也不會自動修改 `main.cpp`。

## 五、需要使用者手動操作

- [ ] 實作完成後，維持可連線 Groq 的網路，在專案頁各測試一次 Analyze Code、Explain Error、Give Hint 與自訂問題。
- [ ] 確認回答語言、內容與串流顯示符合預期。

簡易說明：真實 Groq 回答與網路狀態無法只靠模擬測試確認；除此之外的程式、檔案與測試由開發工具完成。

## 六、本階段不包含

- 長期保存聊天記錄。
- AI 自動覆寫或儲存程式碼。
- 多模型或多家 AI 供應商選擇。
- 教師後台、共享額度與付費訂閱。

## 七、編輯器與 AI Tutor 獨立捲動修正

- [x] 確認共同捲動原因是桌面專案工作區只有最小高度，內容會繼續拉高整個頁面。
- [x] 桌面版專案工作區限制在導覽列下方的可視高度內。
- [x] 程式編輯區、Output／Interactive Console 與 AI Tutor 各自保留獨立捲動區。
- [x] 手機版維持自然上下排列，AI Tutor 使用自己的固定視窗高度。
- [x] 重新執行前端 lint、TypeScript 與 production build。

簡易說明：固定的是工作區視窗，不是內容。程式碼仍由 Monaco 編輯器自行捲動，AI 對話則只在右側面板內捲動，滑鼠停在哪一區就只移動該區。

驗收方式：桌面版將滑鼠放在程式碼、Output 與 AI 回覆區分別滾動，其他區域的位置不應跟著改變；縮小到手機寬度後仍可上下找到所有區塊。

需要使用者手動操作：重新整理專案頁，分別把滑鼠移到程式碼與 AI Tutor 回覆上測試滾輪。
