# Code Tutor APCS 訓練第一階段計畫

- 文件狀態：計畫階段，等待使用者確認後才開始實作
- 最後更新：2026-10-23
- 前置條件：題庫、Judge、分組計分、題目管理與標籤已完成

## 一、目標

讓網站更適合準備 APCS 的使用者練習實作題。第一階段只處理「練習實作題時最直接有感」的三件事，不動計分與判題的核心邏輯：

1. 題目加上 APCS 考點標籤與 1 到 5 的 APCS 級別，可以依考點與級別篩選。
2. 題目頁的範例可以一鍵載入到輸入區，Run 後自動和範例輸出比對。
3. 提交結果顯示更完整：記憶體、各子任務失敗原因、近期提交歷史。

簡易說明：學生要知道「這題屬於哪個考點、大概幾級」「我的程式有沒有過範例」「哪一組子任務為什麼沒過」。這些都是現在缺少、但不需要大改架構就能補上的資訊。

- [x] Judge 已支援子任務分組與逐筆計分，回傳 `duration_ms` 與 `peak_memory_kb`。
- [x] 題目頁開啟時，輸入區會預設放入第一個範例輸入；其他範例只能手動複製。
- [x] 提交結果面板顯示總分、各群組分數與通過筆數，但沒有顯示記憶體、失敗原因與提交歷史。
- [x] `submissions` 資料表已保存使用者的提交；使用者只能讀取自己的紀錄。
- [ ] 以上三項改善尚未實作。

## 三、不在本階段範圍

- 班級、老師與指派題單功能（已確認延後）。
- 觀念題測驗、錯題本、進度儀表板、模擬考（列為第二、第三階段，另立計畫書）。
- Java 與 C 語言支援。
- 歷屆 APCS 原題的收錄；內容以原創的 APCS 風格題為主，避免版權問題。

## 四、執行步驟

### 1. 資料庫：APCS 級別與標準考點標籤

- [ ] 新增 migration：`problems` 加入可為空的 `apcs_level smallint`，限制為 1 到 5。
- [ ] 同一支 migration 以 `on conflict do nothing` 加入標準考點標籤（例如陣列、字串、遞迴、排序、堆疊與佇列、DFS、BFS、動態規劃、貪心、二分搜尋、前綴和、樹、圖論、模擬），不覆蓋現有標籤。
- [ ] 後端 `problem_models.py`、題目管理 API 與讀取題目的程式支援 `apcs_level`，並重新產生前端 API 型別（`npm run gen:api`）。

簡易說明：級別欄位允許空白，所以舊題目不受影響。標準考點標籤只是補上清單，已經存在的標籤不會被改動。

### 2. 題目管理與題庫畫面

- [ ] 題目管理介面可設定 APCS 級別。
- [ ] 題目列表新增「APCS 級別」篩選與卡片徽章，題目詳情頁同樣顯示；沿用現有的 `easy / medium / hard`，不取代。
- [ ] `#` 標籤搜尋沿用既有 AND 規則，確認新標籤能被搜尋。

簡易說明：學生可以選「3 級、陣列」的題目練習；舊的難度篩選照常運作。

### 3. 範例一鍵載入與自動比對（純前端）

- [ ] 每個範例旁加入「載入到輸入」按鈕。
- [ ] Run 完成後，如果目前輸入與某個範例輸入完全相同，顯示「與範例輸出相同」或「與範例輸出不同」；不同時並列顯示預期輸出，比對沿用後端相同的行尾空白規則。
- [ ] 輸入與範例不同時不顯示比對，避免誤導。

簡易說明：Run 只是用你輸入的資料執行；現在多了一個快速確認「這個範例對不對」的步驟，不會建立正式提交。

### 4. 提交結果更完整

- [ ] 結果面板顯示 `peak_memory_kb` 與題目的記憶體限制、`duration_ms` 與時間限制。
- [ ] 後端在每個子任務結果加上 `failure_kind`（答案錯誤、超時、執行錯誤、記憶體超限），只顯示類型，不顯示測資內容。
- [ ] 前端在失敗的子任務旁顯示失敗原因，舊的提交紀錄沒有此欄位時照常顯示。

簡易說明：學生能看到「第 2 組超時」而不是只看到沒過，知道該優化演算法還是檢查邏輯。測資內容與答案依然完全隱藏。

### 5. 近期提交歷史

- [ ] 題目頁新增「我的提交」區塊，列出該題最近 10 次提交的時間、語言、狀態與分數。
- [ ] 點選一筆可把該次程式碼載入編輯器（載入前若有未儲存內容，沿用既有警告）。
- [ ] 未登入時顯示「登入後可查看提交紀錄」。

簡易說明：資料表與讀取權限已經存在，主要是把它顯示出來，並讓學生回頭比較自己的多次解法。

## 五、驗收方式

1. 在題目管理設定某題為 3 級並套用「陣列」標籤，列表依 3 級與 `#陣列` 能找到它；舊題目沒有級別，仍然正常顯示。
2. 點選範例 2 的「載入到輸入」，Run 後畫面顯示輸出與範例是否相同。手動修改輸入後不再顯示比對。
3. 故意送出超時與答案錯誤的程式，結果面板分別在對應子任務顯示超時與答案錯誤，且回應內容沒有任何測資。
4. 提交後在「我的提交」立刻看到新紀錄，點選可載入當時的程式碼。
5. 未登入使用者仍可閱讀題目與 Run，Submit 與提交歷史提示登入。

## 六、需要使用者手動操作

- [ ] 在 Supabase SQL Editor 執行步驟 1 新增的 migration（只有 Supabase 專案擁有者能執行）。
- [ ] 在題目管理介面為現有題目補上 APCS 級別與考點標籤（內容判斷由你負責）。
- [ ] 合併後在 VPS 執行 `git pull origin main && bash deploy/scripts/deploy.sh --restart`。

## 七、風險與注意事項

- APCS 實際的級分制度、題數與時限以官方最新簡章為準，本計畫的「級別」只是練習用的難度分級，不代表官方級分。
- `failure_kind` 必須嚴格只回傳類型，不能帶出輸入或輸出，避免洩漏隱藏測資。
- 提交歷史會讀取最多 10 筆原始碼，前端要限制單次載入量，避免大型程式拖慢頁面。
