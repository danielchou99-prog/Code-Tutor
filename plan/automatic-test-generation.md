# 自動生成測資計畫

## 目標

讓管理員建立題目時，可以依照設定的範圍自動產生輸入測資，並由可信任的官方參考解答計算正確輸出。產生結果必須先預覽、抽查，確認後才加入隱藏測資，不能讓 AI 猜測標準答案後直接發布。

## 目前狀態

- [x] 題目管理頁已能手動新增配分群組、輸入與預期輸出。
- [x] C++ 與 Python 沙箱編譯器已能執行程式。
- [ ] 題目資料尚未保存「官方參考解答」。
- [ ] 尚未定義各題的測資生成規則與固定亂數種子。
- [ ] 尚未有預覽、批次執行與異常測資排除流程。

## 為什麼不能只請 AI 直接生成答案

AI 可以協助提出邊界情況，例如最小值、最大值、重複值或無解情況，但它可能算錯預期輸出。Judge 的標準答案只要錯一筆，就可能把正確程式判成錯誤。因此 AI 最多協助設計候選輸入，最終輸出一定由管理員提供並驗證過的參考解答計算。

## 執行步驟

- [ ] 1. 增加官方參考解答欄位。
  - 簡易說明：每題保存一份不公開的 C++ 或 Python 正確程式，只讓管理員與後端讀取。
- [ ] 2. 建立測資規則格式。
  - 簡易說明：管理員設定整數範圍、陣列長度、是否排序、是否允許重複、字串長度或圖的節點與邊數，不直接手寫每一筆。
- [ ] 3. 支援固定亂數種子。
  - 簡易說明：相同種子會產生相同測資，發生問題時才能重新產生並追查。
- [ ] 4. 自動補入必要邊界測資。
  - 簡易說明：除了隨機資料，也加入最小值、最大值、空結果、重複值與極端排列等容易出錯的案例。
- [ ] 5. 在 Docker 沙箱執行參考解答。
  - 簡易說明：每筆候選輸入交給官方解答計算輸出，並套用逾時、記憶體與輸出大小限制。
- [ ] 6. 建立預覽與抽查畫面。
  - 簡易說明：管理員能看到產生數量、輸入、輸出、執行時間與失敗原因，確認後才匯入測資群組。
- [ ] 7. 加入防呆與去重。
  - 簡易說明：移除重複測資，拒絕參考解答逾時、崩潰或輸出不穩定的結果；失敗時不修改現有題目。
- [ ] 8. 建立測試與操作紀錄。
  - 簡易說明：驗證一般使用者不能使用生成 API，並記錄管理員、題號、規則、種子與生成時間。

## 驗收方式

- [ ] 相同規則與種子能得到完全相同的測資。
- [ ] 預期輸出全部由官方參考解答產生，不由 AI 直接填寫。
- [ ] 參考解答逾時、編譯失敗或崩潰時，不會加入任何測資。
- [ ] 重複輸入會被去除，測資數量與配分顯示正確。
- [ ] 一般使用者無法取得參考解答、隱藏測資或呼叫生成 API。
- [ ] 管理員確認前不會寫入正式 Judge 資料。

## 需要使用者手動操作的事項

- [ ] 提供或確認每道題的官方正確解答。
- [ ] 為每道題選擇生成規則與數量，並抽查預覽結果。
- [ ] 正式部署時確認 VPS 的 Docker 資源限制足以執行批次生成。

## 建議第一版

先支援最常見的「整數、整數陣列、排序陣列」三種生成器。等流程驗收後，再加入字串、矩陣、圖與自訂生成器。這樣比較容易確保答案正確，也能先涵蓋目前多數基礎題。
