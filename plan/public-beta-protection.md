## 一、計畫目標

讓 Code Tutor 從「單一使用者本機測試」前進到「少量使用者可以安全試用」。公開或區域網路上的使用者不能無限制建立 Compiler 容器；系統需要限制請求頻率、同時執行數與排隊數量，並在忙碌時提供清楚回應。

這個階段也會建立安全的區域網路啟動方式，讓同一個私人 Wi‑Fi 上的其他裝置可以完整使用頁面與 Run，但不會直接將開發服務暴露到整個 Internet。

## 三、第一階段：API Rate Limit

### 計畫

- [x] 以直接連線的來源 IP 作為本機 rate limit key。
- [x] `/api/run` 在固定時間範圍內只接受設定數量的請求。
- [x] 超過限制時回傳 HTTP 429、`Retry-After` 與固定格式結果。
- [x] rate limit 數值可透過環境變數調整。
- [x] 加入允許、拒絕與時間窗重置測試。

### 簡易說明

Rate limit 像是每位使用者手上的號碼牌。某個裝置短時間連續按很多次 Run 時，後端會要求它稍後再試，避免一個人占用全部編譯資源。

第一版只使用記憶體保存計數，適合單一 Backend 程序。正式多台 Backend 時會改用 Redis 等共享儲存。

### 完成標準

- 單一 IP 超過限制會收到 HTTP 429。
- 不同 IP 的計數互不影響。
- 時間窗結束後可以再次執行。
- 回應不會建立 Docker 容器。

## 四、第二階段：最大並行數與等待佇列

### 計畫

- [x] 設定同時最多執行的 Compiler 數量。
- [x] 設定最多等待工作數量。
- [x] 等待區已滿時立即回傳 `server_busy`。
- [x] 工作等待超過限制時間時停止等待。
- [x] 無論成功或錯誤，都正確釋放執行名額。
- [x] 加入多請求並行測試。

### 簡易說明

Docker Compiler 是廚房，並行數是同時工作的爐子，等待佇列是在門外排隊的人數。爐子和隊伍都有上限，才能避免電腦因大量請求失去回應。

### 完成標準

- 同時建立的 Compiler 容器不超過設定值。
- 等待區滿時回應清楚，不會無限等待。
- 一個工作失敗不會永久占住名額。

## 五、第三階段：Frontend 狀態顯示

### 計畫

- [x] 新增 `rate_limited` 與 `server_busy` 結果狀態。
- [x] Output 顯示稍後重試的簡單說明。
- [x] 若有 `Retry-After`，顯示大約需要等待的秒數。
- [x] Run 進行中維持 disabled，避免同一頁重複送出。

### 簡易說明

後端拒絕請求時，不能只顯示模糊的「失敗」。使用者要知道是按太快、伺服器忙碌，還是 Compiler 故障，才知道下一步應該等待或回報問題。

### 完成標準

- 三種狀況有不同提示：按太快、伺服器忙碌、服務無法使用。
- 錯誤不會清除編輯器裡的程式碼或 Input。

## 六、第四階段：安全的區域網路存取

### 目前判斷

- 這台電腦目前 Wi‑Fi IPv4 是 `192.168.1.131`。
- Frontend 目前只監聽本機 `127.0.0.1:3000`；先前曾以 `http://192.168.1.131:3000` 測試成功回傳 HTTP 200，但因 Wi-Fi 是 Public，未重新對 LAN 啟動。
- Backend 只監聽 `127.0.0.1:8000`，其他裝置無法連線。
- Windows 將 Wi-Fi `network5g 5` 設為 Public，現階段不可安全開放開發伺服器與 Compiler API。

### 計畫

- [x] 讓 Frontend API 位址依目前頁面 hostname 組合，或由 LAN 環境變數指定。
- [ ] 建立只供私人 LAN 使用的 Backend 啟動指令，監聽 `0.0.0.0:8000`。
- [x] CORS 只允許指定的 Frontend LAN origin，不使用萬用 `*`。
- [x] Next.js 開發模式只允許設定清單內的額外來源。
- [ ] Windows 防火牆規則只允許 Private network，並由使用者確認。
- [ ] 用第二台裝置測試頁面、Run、錯誤提示與 rate limit。

### 簡易說明

現在手機有機會看到網頁，但按 Run 時會去找手機自己的 port 8000。完成這一階段後，手機會改為呼叫電腦的 `192.168.1.131:8000`，而且只有同一個私人網路可以連線。

IP 位址由路由器分配，重新連線後可能改變，因此它不是永久公開網址。正式 Internet 網址要等部署、HTTPS 與網域設定完成。

### 完成標準

- 同一私人 Wi‑Fi 的其他裝置可以開啟頁面並成功執行 C++。
- Public network 不會自動開放 Compiler API。
- CORS 不接受未列入允許清單的網站。

## 八、需要使用者手動操作

1. 確認 `network5g 5` 是自己信任的家用 Wi‑Fi，再到 Windows 設定將網路設定檔改成「私人」。若是公共或共用 Wi‑Fi，請勿修改。
2. LAN 測試時，讓測試裝置與電腦連接同一個可信任的私人 Wi‑Fi。
3. 若 Windows 顯示防火牆提示，只允許「私人網路」，不要勾選「公用網路」。
4. 用第二台裝置開啟提供的 LAN 連結並按 Run。
5. 正式部署時選擇雲端主機、網域與付款方案。

其餘程式、設定、測試與文件更新由開發工具處理。
